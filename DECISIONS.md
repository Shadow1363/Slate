# Decisions

Choices made where SPEC.md is silent, or confirmed from its "Open decisions" table. Newest last.

## Confirmed open decisions (2026-11-22)
Every default in SPEC.md › Open decisions is kept: the name **Slate**; scene headings as `#` lines plus auto-detected `INT./EXT.`; acts as optional numbered files in `script/`; **macOS 15** minimum; **Developer ID, unsandboxed**; **US Letter** default page size; storyboard as **scene folders + `frames.json`**; a **simple built-in sketch pad**.

## Milestone 1

| # | Decision | Why |
|---|---|---|
| 1 | No third-party dependencies in M1. Yams and swift-markdown are needed from M4 and will be asked about first. | project.json and themes are plain JSON, which Foundation covers. |
| 2 | Slate writes all JSON pretty-printed, with sorted keys, unescaped slashes and a trailing newline (`SlateJSON`). | One stable style gives small diffs and byte-identical round trips. |
| 3 | Unknown keys in `project.json` are kept and written back. | Hand edits and fields from newer versions survive a save. |
| 4 | `project.json` keys: `name`, `id` (`p-<uuid>`), `schemaVersion` (1), `pageSize` (`letter`/`a4`), `settings` (object), optional `theme` (one theme name that overrides the app theme in both appearances). | The smallest set the spec needs. A single theme name is easier to read than separate light and dark overrides. |
| 5 | Migration backups go to `.slate/backups/project-v<old>-<UTC time>.json`. A newer schema is refused rather than opened read-only. | Never risks writing over fields this version doesn't understand. |
| 6 | Templates differ only in starter files. Feature has 3 act files and Short has `script.md`. TV Pilot has a teaser plus 4 acts. Blank has `script.md`, an empty title page and no note-type folders. Act files start with a boneyard label such as `/* ACT ONE */`. | Matches "templates only differ in starter files". A boneyard comment is invisible in Publish. |
| 7 | The project folder name is the title, with `/` and `:` replaced by `-` and leading dots removed. Spaces are kept. | Finder-readable (`My Film/`, as in the spec). |
| 8 | Saving: ⌘S, plus autosave 2 s after the last keystroke. Before each save Slate re-reads the file, and if it changed outside, it shows a conflict instead of writing. Nothing autosaves while a conflict or deletion banner is showing. | A Mac app shouldn't lose work, and autosave must never overwrite an outside edit. |
| 9 | Outside-change rules: no unsaved edits → reload. Unsaved edits → "Keep Mine / Load Theirs". File gone → keep the buffer and offer "Save Again / Close". If the outside change matches the buffer or is undone, the banner clears on its own. A reload is an undoable edit in the text view. | "Reload without losing unsaved edits." |
| 10 | Watching uses FSEvents (file-level, 150 ms latency) **and** an `NSFilePresenter` on the root. Slate's own writes pass that presenter to `NSFileCoordinator`. Slate's own FSEvents echoes are harmless, because the disk text equals the last-known text. | FSEvents catches editors and git, which don't coordinate. The presenter catches iCloud. |
| 11 | Text files must be UTF-8. Other encodings are refused, not converted. Line endings are kept as found. | Lossy decoding would corrupt the file on the next save. |
| 12 | Bookmarks are created with `.withSecurityScope`, falling back to plain bookmarks if that fails. `startAccessingSecurityScopedResource` is called on resolve. A project in the Trash counts as missing. | Moving to the App Store sandbox later stays a small change (per the spec). |
| 13 | The library lives in `~/Library/Application Support/Slate/library.json`. Projects removed by the user are remembered in `ignoredPaths`, so scanning a watched folder doesn't add them back. | Remove from Library must stick. |
| 14 | Theme files are deep-merged JSON: objects merge key by key, and arrays and values are replaced. A theme is identified by its `name` field (case-insensitive), not its file name. User themes can't reuse a built-in name. Each theme has an `appearance` (`light`/`dark`), inherited from its base. | The spec's own example (`"base": "dark"` plus a few tokens) works unchanged. |
| 15 | Token names were added for groups the spec only describes. Examples: `editor.font`/`size`, `script.<element>.{font,size,weight,color,uppercase,spaceBefore}`, `canvas.laneColors`. | A complete, documented token set. `ResolvedTheme.swift` is the reference. |
| 16 | Courier Prime isn't bundled yet, so Courier-family names fall back to Courier New, then Courier. Bundling Courier Prime (SIL OFL) for Publish will be asked about before M3. | Bundling a font is a third-party asset. |
| 17 | `Slate.xcodeproj` is generated and git-ignored. `App/Info.plist` is generated by XcodeGen too, but committed. | Reproducible from `project.yml`, as asked. |
| 18 | Bundle ID `app.slate.mac` is a placeholder until Developer ID signing in M12. | No team or domain chosen yet. |
| 19 | Tests use Swift Testing (`import Testing`). The sample project is in `Fixtures/SampleProject/`, and tests work on temp copies of it. | Built into Xcode, with parameterised tests. |
| 20 | Until each area's real editor exists, every area shows a temporary file list and a plain-text editor. | Needed to show the M1 "done when" (outside edit → reload). |
| 21 | Opening the same project twice focuses its window. `WindowGroup(for: URL.self)` handles this. | The simplest correct behaviour. |

## Milestone 2

| # | Decision | Why |
|---|---|---|
| 22 | Headings typed in the editor are written as `# INT. …`, even though `INT.` would be detected alone. | Every editor-made heading reads back as a heading, whatever its text (`# MONTAGE`). |
| 23 | When Tab sets a line's kind and the text needs it, the editor adds the Fountain marker: `>` for a transition that doesn't end in `TO:`, `@` for a cue that isn't all caps, `!` for action that looks like a heading, cue or transition. | The file must read back as what the writer chose, in any Fountain app. |
| 24 | The parser takes a "hint" for the caret's line, so an empty line or a cue with no dialogue yet shows as what you are typing. The hint is dropped when the caret leaves the line, and the file decides from then on. | Fountain can't express "empty character line", and the file should never carry editor state. |
| 25 | Return follows Final Draft's defaults: Dialogue → Action, Transition → Heading. An empty cue, heading or transition plus Return turns back into Action. ⌥Return is a plain line break. Return in the middle of a line just breaks it. | Familiar to screenwriters and predictable. |
| 26 | Paragraph breaks are real blank lines (Return inserts `\n\n` where Fountain needs a blank line). The theme's `spaceBefore` is not used in Draft view. | Fountain spacing is in the text. Adding theme spacing would double it. |
| 27 | Scene IDs are `s` plus at least 3 digits, one more than the highest in the script. They are added when you press Return on a heading or leave it, not when a file is opened. | Opening a file never rewrites it. Typing a heading tags it straight away, as the spec says. |
| 28 | The scene tag stays visible in the editor as a small chip-coloured tag rather than hidden. | Hiding characters in TextKit 2 makes caret movement and selection confusing. It can be revisited with Page view in M3. |
| 29 | Cues, headings and transitions are upper-cased as you type, in the file itself. | Fountain needs capitals for cues, and NSTextView has no display-only text transform. |
| 30 | Autocomplete is inline type-ahead (the selected remainder) rather than a pop-up list. | Fully keyboard-driven: keep typing, Tab/→/Return to accept, Esc to drop. |
| 31 | The editor shows one act file at a time. The navigator and ⇧⌘O cover the whole script. | Editing joined files in one view would need cross-file edit mapping. This keeps every file write simple. |
| 32 | Draft view layout: Courier-style 10 characters per inch, so 1 inch = 6 × the theme's action font size. The 6-inch column is centred. Character starts at 2.2", parenthetical at 1.6–3.6", dialogue at 1.0–4.5" from the column edge. | The Publish table in SPEC.md, measured from the 1.5" left margin. |
| 33 | Eighths and timings are estimates until M3: lines wrap at 60/35/20 characters (action/dialogue/parenthetical), 55 lines per page, at least 1/8 per scene. They are shown with `~`. | Gives useful numbers now. M3's page engine replaces them. |
| 34 | Character names for autocomplete and spelling also come from `universe/characters/*.md` frontmatter, read with a small line parser (`name:`, `aliases:`), not Yams. | Avoids adding a dependency before M4. The full YAML parser arrives with Universe notes. |
| 35 | SlateUI gets its own test target, which drives `ScriptEditorController` with real keystrokes on a windowless `NSTextView`. | The editor's rules are where regressions would hurt most, and this tests them without UI automation. |

## Milestone 3

| # | Decision | Why |
|---|---|---|
| 36 | Courier Prime (SIL OFL 1.1) is bundled in SlateExport and loaded straight from its files for Publish. It's also registered for the app so editor themes can use it. | Your choice. Output is identical on every Mac, whatever fonts are installed. |
| 37 | Layout widths are measured in characters (10 per inch): action and headings 61, dialogue 35, parenthetical 26, cue 38. A lone trailing `--` may hang one character past the edge. | Calibrated against the *Brick & Steel* reference PDF: 61-character action lines fit and 62 wrap, except for a hanging `--`. A 26-character parenthetical fits on one line. |
| 38 | Positions: character 3.5", parenthetical 2.9", transition right edge 7.1", page number right edge 7.25" and 0.5" from the top. These replace SPEC.md's 3.7" and 3.1". | SPEC.md asked for these to be checked against real output in M3. The reference PDF (and Final Draft's defaults) use these. |
| 39 | Two blank lines before scene headings and one before other elements. Spacing comes from elements, not the file's blank lines. A setting (`headingSpacing`) allows 1. | Matches *Brick & Steel* and Final Draft. *The Last Birthday Card* was made with 1, and its test uses that. |
| 40 | Lines per page = (page height − 2") × 6: 54 on Letter, 58 on A4. | Both reference PDFs use 54 lines. |
| 41 | Dialogue and action only split after a line that ends a sentence (or a source line), with at least 2 lines each side. | Final Draft's behaviour. The *Last Birthday Card* PDF splits action anywhere, which accounts for most of its 1–2 line differences. |
| 42 | Automatic (CONT'D) is added when the same speaker resumes after action only, and resets at each scene heading. It isn't added to dual dialogue. | Final Draft's default, and you chose it on by default. |
| 43 | Scene numbers in the margins are each scene's position in the script. Locked numbers are M11. | Simplest correct numbering until production mode. |
| 44 | Eighths are counted per page per scene (including blank lines before the heading), each portion rounded and at least 1/8, then summed. | The industry convention for scene length. |
| 45 | Exact eighths and pages are computed 300 ms after typing stops, off the main thread. Until then the UI shows `~` estimates. | Keeps typing fast (layout takes about 2–9 ms per run) while the numbers still match the PDF. |
| 46 | Page view is a read-only PDFView of the real renderer's output. Editing stays in Draft view. | Guarantees Page view equals print. An editable paginated TextKit view would be a large separate project. |
| 47 | Print is ⌥⌘P because SPEC.md gives ⌘P to Quick Open. Publish PDF is ⇧⌘E. | Avoids a shortcut clash. |
| 48 | Exports go to `exports/<Project> – YYYY-MM-DD.<ext>`, adding ` 2`, ` 3`… instead of overwriting. | Nothing is ever deleted silently. |
| 49 | On import, Fountain `[[notes]]` become `/* note: … */`. | Slate uses `[[…]]` for links. Turning notes into comments keeps their text without creating broken links. |
| 50 | Fountain export writes act files as `# Sections` (titles from the file names) and `.FORCED` headings when needed. | Re-importing the export gives back the same act files. |
| 51 | FDX: consecutive action or centred lines (single line breaks) become one paragraph with line breaks. Slate IDs are kept in a `SlateSceneID` attribute. Boneyard and synopsis aren't exported. | A round trip paginates the same. Final Draft ignores unknown attributes. |
| 52 | The title page prints title, credit, authors, source and draft date centred from line 18, with contact bottom-left. | SPEC.md's layout. (The reference puts the draft date bottom-left. That's a style difference that doesn't affect pagination.) |
| 53 | The reference fixtures are fountain.io's own sample scripts and PDFs. *Big Fish* is left out because it's a commercial screenplay. | Public Fountain samples, with attribution in `Fixtures/Fountain/README.md`. |
| 54 | Quotes print as typed (no smart quotes in Publish). | Matches Final Draft's typewriter style. The file stays plain. |
